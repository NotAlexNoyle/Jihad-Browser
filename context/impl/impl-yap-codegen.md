# Implementation: the YAP code generator, vendored and patched

Implements the last acceptance criterion of `cavekit-ipc-contract.md` **R1** ("if regenerated, it
is regenerated from the definition, not hand-edited"). Read that kit first; this file records what
was built, what was measured, and what a regeneration does and does not reproduce.

## 2026-08-15 — regeneration now reproduces the shipped interface with zero hand edits

### The gap this closed

`BrowserServerBase.{h,cpp}` and `BrowserClientBase.{h,cpp}` are generated, but the generator lived
outside this repo, in the separate `ref-BrowserServer` checkout. The 2026-08-10 work had already
established that its `.defs` could not be used (no 0x1600; stale on the `int32 chr` that KeyDown and
KeyUp actually carry) and had landed a corrected `.defs` in the tree. What remained was structural
and no `.defs` edit could reach it: `YapCodeGen.cpp` emitted **every** async command as `= 0;`, so
it could not produce the one declaration that must not be pure virtual —
`asyncCmdSetExtraBuffer` (0x1600), whose empty default body is what makes the command optional on
the server side and therefore safe to add to a frozen contract (R1 AC2). That body had to be
restored by hand after every regeneration.

### What landed

- **`render/browserserver/CodeGen/YapCodeGen.cpp`** — the generator, vendored from
  isis-project/BrowserServer, keeping its Apache-2.0 header and carrying a change notice under it
  (Apache-2.0 §4(b)). Attribution added to the repo `NOTICE`. Three patches:
  1. `ignoreLine()` advances its pointer. Upstream scanned for a non-space character without ever
     advancing, so a `.defs` line starting with a space spun forever — the trap the kit recorded.
     Blank runs are skipped, tabs and CR count as blank, and an indented comment is now allowed.
  2. The type field takes space-separated flags: `async optional; …`. Unknown flags are a parse
     error, not silently ignored.
  3. `optional` async commands are emitted server-side as a non-pure virtual with an empty default
     body (`{ (void)proxy; (void)arg; … }`) plus a two-line comment saying why, and the client
     header gets a matching note on the sending half. `optional` is rejected on `sync` and `msg`,
     where the semantics are not defined — no such id exists, and a sync command silently returning
     zeroed out-args would be worse than a compile error.
- **`render/browserserver/CodeGen/CodeGen.pro`** — the upstream qmake project, vendored unchanged.
- **`render/browserserver/CodeGen/README.md`** — build + regenerate loop, why this generator and
  this `.defs` are the only valid ones, and the list of residual textual differences below.
- **`BrowserYapCommandMessages.defs`** — 0x1600 marked `async optional`; the header block rewritten,
  since it documented the hand edit and the hang as live facts.
- **`build/webos-oe/check-yap-contract.sh`** — comment block and failure epilogue corrected; they
  told the reader to re-apply a hand edit that no longer exists. No new assertion was added: the
  script already asserts the 0x1600 arm and the non-pure-virtual declaration, and `override` in
  `JihadBrowserServer.h` guards the declarations at compile time.

### Verified

Host only — Qt 5.15.11, g++ 14.2.1, qmake 3.1. No device operation, no ARM build.

| Check | Result |
|---|---|
| Vendored generator builds | Yes, warnings only (upstream's own deprecated `QString::SkipEmptyParts`) |
| Vendored vs upstream generator on the **upstream** `.defs` | All four output files **byte-identical** — the patches change nothing for input upstream already accepted |
| Generated `BrowserServerBase.cpp` vs shipped | Exactly the four known cosmetic diffs, **zero structural diffs** |
| Generated `BrowserServerBase.h` vs shipped | The 0x1600 hand edit is now **generated byte-for-byte**; three cosmetic diffs remain (below) |
| `check-yap-contract.sh` against the generated four-file set | **Zero defects** ("73 commands, 58 messages, both sides agree"). Best previously possible was exactly one |
| `check-yap-contract.sh` against the tree as it ships | Still passes — no regression |
| Space-hang trap | A `.defs` with an indented comment, an all-blank line and an indented command: upstream generator **times out at 10 s (exit 124)**; vendored generator parses it and exits 0 |
| Flag error paths | `sync optional`, `msg optional` and `async bogus` each exit non-zero with a named message |

The four cosmetic `.cpp` diffs, unchanged from what 2026-08-10 recorded: the copyright year (the
generator stamps the current year), the hand-written parenthetical after `// SetExtraBuffer` in the
case arm, and the two `int32_t chr = 0;` lines re-indented from spaces to a tab.

### What a regeneration still does not reproduce byte-for-byte

None of these needs a hand edit re-applied; they are the difference between today's bytes and a
fresh generation, and both are correct.

- **Server `.h`**: the copyright year; the comment above the optional declaration is worded
  generically rather than mentioning the third buffer; and `asyncCmdSetExtraBuffer` is **declared**
  one position earlier, right after `asyncCmdConnect`. That last one cannot be fixed in the `.defs`:
  the shipped `.h` and the shipped `.cpp` disagree with each other about where 0x1600 sits, because
  each was hand-edited separately, and one `.defs` ordering drives both. The generated pair is
  self-consistent. It is declaration order within one class in one binary and has no wire effect.
- **Client pair**: not byte-comparable at all, and this predates the task. The shipped
  `BrowserClientBase.{h,cpp}` came from an **older YapCodeGen vintage** — four-space indent, no
  license block emitted — so a whitespace-insensitive diff is the only meaningful one. Under it the
  only differences are the license block, the same 0x1600 ordering, comment wording, and two
  debug-path residues that a regeneration would *fix*: shipped `sendRawCmd` has no `SetExtraBuffer`
  arm at all, and its KeyDown/KeyUp raw-argument parsing still uses `strtoul` left over from when
  those were `uint16_t` (generated uses `atol`, which is what `int` maps to). `sendRawCmd` is a
  text-console path; none of this touches the wire, and the guard passes on the generated pair.

### Deliberately not done

- **`render/browserserver/Src/` and `render/adapter/` were not touched.** The goal was proving
  reproduction, not rewriting live code, and another agent held the ARM objdir this wave — a header
  change landing mid-build is how you get a mixed vtable and a crash nobody can explain. Adopting
  the regenerated files is a separate, deliberate act; the README says what changes when you do.
- **No second build-time check.** The kit forbids it: `override` in `JihadBrowserServer.h` already
  fails the compile if either declaration is lost, and `check-yap-contract.sh` covers the dispatch
  arm, which the type system cannot see.
- **The copyright year was left following the clock**, as upstream wrote it. Pinning it would make
  regeneration byte-exact on that line, but the emitted notice is HP's and stamping a year on it is
  a licensing decision, not a codegen one (`cavekit-licensing-branding.md`).
