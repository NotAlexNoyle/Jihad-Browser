     card-side.

## Traps this session cost real time on — do not re-learn

- **`Mojo.stringifyJSON` does not exist** in this framework build (`Mojo.parseJSON` does).
  `jihad-history.js` used it, so **Mojo history never persisted**. Use `JSON.stringify`.
- **`Mojo.Log.warn` is below the card's log threshold** and never reaches
  `/var/log/messages`. Use `Mojo.Log.error` for probes.
- **Guard idempotent appends on YOUR OWN marker**, never on the name of the thing you are
  overriding — upstream almost certainly sets it too, so `grep -q <prefname>` matches and
  your append is silently skipped while reporting success.
- **Never bound a block delete by its endpoints without asserting what is between them.**
  Doing that removed five unrelated preference handlers from `app/source/Preferences.js`
  and, with a one-line menu change, took the search selector, JS/Flash toggles and all four
  clear-data actions out of the Enyo product.
- **The device screenshots itself**: `luna-send -n 1
  palm://com.palm.systemmanager/takeScreenShot '{"file":"/tmp/x.png"}'`, and
  `getSystemStatus` reports `ime.visible`. Frames are framebuffer-oriented (`magick -rotate
  90`). This is the fastest way to diagnose UI; most bugs here were invisible in source.
- **`sleep N | novacom run` typed inline is refused by the harness sleep guard** — wrap it in
  a script. A `novacom run ... cat > file` without held stdin yields a 0-byte file.
- **`chrome://jihad-prefs/content/...`**: the `/content/` segment is load-bearing.
  `nsChromeProtocolHandler` grants the system principal only for that path prefix.

## Security notes worth keeping

- `adoptFromUrl` (Enyo + Mochi) is gated on the url **path** (`about:preferences` /
  `about:settings`), not the scheme. `about:blank` is content-loadable, so a scheme-only
  check let any visited page rewrite the home button — and a `javascript:` home target runs
  in page context, since the daemon's url fixup passes `javascript:` through.
- Stored home/link urls are allowlisted to `https?:` and our own `about:` pages, in both the
  card and the page.
- `about:preferences` deliberately does NOT set `URI_SAFE_FOR_UNTRUSTED_CONTENT`, which is
  what keeps web content from reaching it. Verified against `nsAboutProtocolHandler`.

## Decorative-control trap (cavekit-preferences-ui.md R2)

A pref existing is not a pref being honored. Confirmed decorative in this embedding:
- `javascript.enabled` — daemon gates script per-PAGE on the docShell too
  (`GoannaRenderPage::SetJavaScriptEnabled`). Row removed.
- `general.useragent.override` — `EngineHost` rewrites it on EVERY daemon start. Row removed.
- `intl.accept_languages` — a LOCALIZED pref; `getCharPref` returns
  `chrome://global/locale/intl.properties`. Read fixed to `getComplexValue`.
- `dom.disable_open_during_load`, `network.cookie.cookieBehavior`,
  `font.minimum-size.x-western` — correct globals, BUT the card re-applies its db8 copies at
  every launch (`BrowserApp.browserPreferencesChanged` -> `applyPreference`), overwriting the
  page. Rows kept; they become correct when R5 lands.
