# BrowserAdapter ↔ BrowserServer IPC contract (YAP)

**This file is the wire REFERENCE — what the commands, messages and framebuffer actually are.**
The *requirement* that they stay byte-identical, the regeneration rule, and the compatibility
argument for the one additive command all live in `context/kits/cavekit-ipc-contract.md` R1-R5 and
are not repeated here; that kit is the single source of truth for what must hold and whether it
does.

Source of truth for the wire itself: `BrowserServerBase.h` (autogenerated from `YapCodeGen`) and
`BrowserPage.h` in the isis-project BrowserServer repo (cloned to `../ref-BrowserServer`).
Transport is **YAP** (YapServer/YapProxy/YapPacket, from `libYap.a`) over a local socket, plus a
**shared-memory framebuffer**.

## The ONE divergence: `asyncCmdSetExtraBuffer` (0x1600), added 2026-08-10

Every stock command and message keeps its id, argument list and byte order. One
**new** command was added, and nothing else:

    0x1600  asyncCmdSetExtraBuffer(int32 sharedBufferKey3, int32 sharedBufferSize)

Why `connect`/`thaw` could not carry it, and why adding an id is safe in both directions when
changing one would not be: `context/kits/cavekit-ipc-contract.md` R1 AC2.

**What it buys** (device, single Flash instance, measured both ways): with two
buffers the daemon can only paint into the one the adapter is not holding, so
every frame costs a full adapter round trip — `deferred` climbed 11 → 38 → 77 as
the plugin's draw rate rose while completed paints stayed pinned near 26/s. With
three, `deferred` is **0** and `wanted` equals `done` (57/57, 65/65, 55/55),
composite runs 27.1–32.2 fps, and the frame-gap **maximum** — which is what reads
as stutter — fell from 127 ms to 52–57 ms. Cost: one more full-page SysV segment
(~12.6 MB at 960x1400) per page instance, allocated best-effort; if that
allocation fails the adapter simply runs on two.

**Regenerating.** Use **this tree's** generator and `.defs`, both in
`render/browserserver/CodeGen/` (build + run instructions in the README there), never the upstream
copies in `../ref-BrowserServer/CodeGen`. Measured 2026-08-10 by building `YapCodeGen.cpp` against
Qt 5.15 and running it: the upstream `.defs` has no 0x1600 **and** is stale on KeyDown/KeyUp
(0x1008/0x1009), which it still declares as two `uint16_t` while every generated file here reads a
third `int32 chr`. Regenerating from it rewrites two live commands from 12 wire bytes to 4. The
upstream *generator* is equally unusable, because it emits every async command as `= 0;` and so
strips `asyncCmdSetExtraBuffer`'s empty default body — the thing that makes 0x1600 optional on the
server side. That gap was closed on 2026-08-15 by vendoring and patching the generator: the
`.defs` line now reads `async optional; SetExtraBuffer, …` and the default body is generated, so a
regeneration needs **no hand edit at all**. `build/webos-oe/check-yap-contract.sh` fails the build
on any of this and passes on the generated pair with zero defects.
What a regeneration owes the contract: `context/kits/cavekit-ipc-contract.md` R1 AC3.

## Framebuffer model

- On `connect`/`thaw` the adapter passes `sharedBufferKey1`, `sharedBufferKey2`,
  `sharedBufferSize` — two SysV shared-memory segments (double buffering) sized
  `pageWidth*pageHeight*4` (BGRA/ARGB32, see `BrowserOffscreenInfo.h` /
  `BrowserOffscreenQt`).
- BrowserServer renders the page into the inactive buffer, then sends
  `msgPainted(sharedBufferKey)` naming which segment is ready.
- The adapter blits that segment to the card surface and, when done, calls
  `returnBuffer(sharedBufferKey)` so the server can reuse it.
- `freeze`/`thaw` detach/reattach the buffers for backgrounded cards (memory
  reclaim). `setWindowSize` / `setVirtualWindowSize` resize the surface and the
  content viewport respectively.

## Implication for the Goanna port

`render/browserserver/` keeps: the YAP server, the shared-buffer plumbing,
the daemon/LunaService registration, page-manager, SSL/cert glue.
`render/goanna/` replaces the body of `BrowserPage`: an `nsIWebBrowser` driven
into an offscreen widget, painting into the shared buffers and emitting the
messages above from Goanna listeners. See `../render/goanna/PORT-MAP.md`.
