== The dead light sensor: a patch package (the owner's ask of 2026-11-08, "make 1 into a .patch to be installed via preware")
packaging/patches/touchpad-light-sensor-off/ (control, postinst, prerm, data/touchpad-light-sensor-off.patch, README),
built by packaging/patches/build-patch-ipk.sh into net.riverstonerelay.patches.touchpad-light-sensor-off_1.0.0_all.ipk.
How sensord polls: /usr/bin/usd_choose_conf.sh picks /etc/usd/usd_topaz-Wifi_default.xml here (boardtype=topaz-Wifi-pvt;
the -3G file on a 4G TouchPad) and libusd loads the <config> drivers in it: mpu3050 (accel+gyro), lsm303dlh (compass),
isl29023 (the light sensor, I2C bus 0 at 0x44, read by sensord itself over /dev/i2c-0). The patch comments the
<isl29023> block out of both files (XML well-formed; the other two drivers untouched) and restarts sensord.
Live, 30 s at idle, stock / patched / patched / stock: the kernel's log lines 101 / 0 / 0 / 99 a second; sensord 621 /
473 / 481 / 571 jiffies (21 -> 16 % of a core); system time 16.4 / 10.8 / 12.4 / 16.9 %; idle 66 / 76 / 71 / 68 %.

transfers (three subscribers poll the accelerometer: the window server, Atlas's sensor bridge, and one more), not for
the dead address; the morning's "240 error interrupts a second" was this traffic, mis-read as errors.
