Getting a context (rounds 281-284: getContext null in r281-r282, the GL error in r283, a context in r284)
  The headless build's GL provider is the null one: WebGL now asks EGL on the GPU path (WebGLContext.cpp).
  The headless GfxInfo answered UNKNOWN for WebGL's OpenGL feature, which reads as blocklisted: OK on the
  GPU path (widget/headless/GfxInfo.cpp).
  The Adreno 220 driver answers GL_INVALID_ENUM for GL_STENCIL_BACK_WRITEMASK, and the error failed the
  context's init ("GL error 0x500 occurred during WebGL context initialization"): queried in its own
  error scope, the front mask stands in (WebGLContextValidate.cpp).
  Software path (NOGPU=1, r312 and before): getContext returns null ("Refused to create native OpenGL
  context"): WebGL stays off.

Getting frames to the compositor
  the basic surface (read back from the canvas's texture framebuffer, r284-r285)  page 8.6-8.9 fps
  the read through the context's own 1024x1024 pbuffer (r312)               page 16.7-17.4, card 12.9-13.9
  one share group, the compositor samples the canvas's texture (r287-r312)  page 21.5-25.1, card 18-20.5
  The driver has no EGLImage from a GL texture (eglCreateImageKHR EGL_BAD_PARAMETER, gpu-bench.c
  section 17), so the zero-copy road is a share group: every pbuffer context on the GPU path under a
  1x1 root (GLContextProviderEGL.cpp). The canvas's frames go as the shared GL texture surface
  (ClientCanvasLayer.cpp). JIHAD_GPU_NO_SHARE=1 keeps contexts unshared (the pbuffer read).
  The large pbuffer only when unshared (r301: no difference shared, 4 MB of GPU memory a context).

Context loss and teardown
  The second WebGL page closed faulted in libGLESv2 (set_framebuffer, gl2_surface_update_writeonly_flag),
  shared (r290-r293) or not (r296): the destroyed context was still current on its thread. Released before it is
  destroyed (GLContextEGL's destructor): 4 and 8 open/close cycles of the card on the cube (each build
  since, the final one included), no fault.
  WEBGL_lose_context lose and restore (?lose=1, twice, the final build included): the page rebuilds its
  objects and draws on (24.8 fps "restored"), no fault.
